# 供应链智能协同设计文档

## 1. 背景

本设计用于在现有 `dtcall` 项目内完整落地以下业务能力，而不是依赖第三方平台或导入数据做演示闭环：

1. 计划侧品牌需求预测与备料评审
2. 库存管理维度的 AI 预警与分析
3. 物控 PR 智能审核与一键审批
4. 采购委外发料齐套提醒与闭环
5. 采购单价智能拆解与合理性复核
6. 研发打样登记、到货提醒、领样闭环

当前项目已具备生产、库存、审批、消息、AI 工作流与业务 AI 结果标准化能力，因此本次建设目标不是新增孤立 AI 页面，而是建设一个复用现有底座的供应链协同业务域。

## 2. 设计目标

### 2.1 业务目标

1. 将计划、采购、仓库、研发之间的协同流程转为系统内闭环
2. 将人工判断为主的备料、PR 审核、单价复核、打样提醒转为“规则引擎 + AI 辅助 + 人工确认”
3. 保证所有关键动作可追溯、可审计、可提醒、可统计
4. 保留高风险动作的人审边界，不让 AI 直接决定关键写操作

### 2.2 技术目标

1. 新增独立业务域模块，避免把规则散落到 `production`、`inventory`、`approval`、`message` 中
2. 尽量复用现有模型和页面模式，不重复建设主数据
3. 所有智能分析统一输出结构化结果，便于页面复用、审计和测试
4. 所有核心单据都定义明确状态机

## 3. 方案选择

本次采用“新增供应链智能协同域模块，底层复用现有模块”的方案。

推荐新增应用：`apps.supply_chain`

推荐原因：

1. 需求已超出单个模块扩展，属于跨计划、采购、仓库、研发的复合协同域
2. 若继续散点扩展现有模块，后续规则、页面和验收会快速失控
3. 若直接重构为通用供应链中台，范围过大，影响现有稳定模块

## 4. 模块边界

### 4.1 新模块职责

`apps.supply_chain` 负责以下业务域：

1. 需求预测与备料评审
2. 委外发料齐套闭环
3. PR 智能审核
4. 单价智能复核
5. 打样与领样闭环
6. 供应链事件日志与驾驶舱

### 4.2 复用现有模块

1. `apps.production`
   - `BOM`、`BOMItem`
   - `ProductionPlan`
   - `MaterialRequest`、`MaterialIssue`
   - 交期预测服务
2. `apps.inventory`
   - `InventoryItem`
   - `Inventory`
   - `StockTransaction`
   - `PurchaseOrder`、`PurchaseOrderItem`
   - `PurchasePriceHistory`
   - `InventoryAlert`
3. `apps.contract`
   - `Supplier`
   - `Product`
4. `apps.approval`
   - 审批实例、审批任务、审批记录
5. `apps.message`
   - 消息分类、通知推送、用户消息关系
6. `apps.ai`
   - 业务 AI 结果标准化
   - AI 工作流
   - 文档解析 / 结构化输出

## 5. 核心数据模型设计

### 5.1 需求预测与备料

1. `DemandForecastPlan`
   - 预测周期、预测类型、责任人、状态、版本
   - 作用：承载一次正式预测任务
2. `DemandForecastSnapshot`
   - 关联预测计划与产品
   - 保存出货、库存、在制、采购在途、人工修正等输入快照
   - 作用：为回溯准确率和审计提供稳定快照
3. `DemandForecastResult`
   - 预测值、安全库存、建议备料量、置信度、风险级别、摘要
   - 作用：承载结构化预测结果
4. `MaterialPreparationReview`
   - 备料评审单
   - 关联预测结果，支持审批、评审结论、备注

### 5.2 委外发料齐套

1. `OutsourceIssueOrder`
   - 关联产品、供应商、生产计划、发料状态
   - 作用：承载委外发料全过程
2. `OutsourceIssueItem`
   - 关联订单、BOMItem、库存物料
   - 保存应发量、可用量、缺口量、齐套状态、规格校验状态
3. `OutsourceIssueStatusLog`
   - 记录齐套校验、备料完成、发料完成、通知发送等事件

### 5.3 PR 智能审核

1. `PRReviewRule`
   - 异常尾数单、返工单、试产单、紧急单、LT 不足等识别规则
2. `PRReviewTask`
   - 承载单次 PR 审核任务
   - 保存来源、命中规则、建议动作、审批模式、人工确认结果
3. `PRReviewEvidence`
   - 保存命中的判断依据和解释，便于审计与人工复核

### 5.4 单价智能复核

1. `PriceReviewOrder`
   - 关联采购单或采购物料、供应商、上传文件、复核状态
2. `PriceReviewDocument`
   - 存规格书文件、OCR 文本、结构化提取结果
3. `PriceReviewComponent`
   - 原材料、工艺、人工、损耗、包装物流、利润等拆解项
4. `PriceReviewConclusion`
   - 保存合理性结论、异常项、建议议价点、人工确认结论

### 5.5 打样闭环

1. `SampleRequest`
   - 打样编号、物料、研发工程师、采购负责人、供应商、交期、状态
2. `SampleReceipt`
   - 到货登记、照片、数量、到货时间、归属信息
3. `SamplePickupRecord`
   - 领样确认、领样时间、超时状态

### 5.6 横向审计

1. `SupplyChainEventLog`
   - 所有关键动作统一写事件日志
   - 支撑报表、AI 问答、问题追溯、验收核查

## 6. 关键状态机

### 6.1 委外发料单

`draft -> checking -> shortage / ready -> picking -> issued -> notified -> closed`

### 6.2 PR 审核任务

`pending -> rule_matched -> auto_approved / manual_review -> done / rejected`

### 6.3 单价复核单

`draft -> parsing -> cost_breakdown -> reviewing -> exception / approved -> archived`

### 6.4 打样单

`draft -> ordered -> received -> pickup_pending -> picked_up -> closed`

### 6.5 预测计划

`draft -> running -> generated -> reviewing -> approved / rejected -> archived`

## 7. 规则引擎与 AI 分工

### 7.1 规则引擎负责

1. BOM 应用量换算
2. 当前库存、在制、在途、缺口计算
3. 安全库存、覆盖天数、缺料风险计算
4. PR 异常识别
5. 历史价格区间、偏离阈值计算
6. 打样超时判定

### 7.2 AI 负责

1. 预测说明、风险解释、问答
2. 规格书 OCR 解析与参数抽取
3. 单价拆解说明与异常溯源说明
4. 审批摘要、评审摘要、提醒文案
5. 管理驾驶舱摘要

### 7.3 边界约束

1. AI 不直接审批 PR
2. AI 不直接确定采购价
3. AI 不直接修改库存、发料或打样状态
4. 所有高风险动作必须通过规则校验和人工确认

## 8. 页面与入口设计

### 8.1 新模块菜单

1. 供应链智能驾驶舱
2. 需求预测与备料评审
3. 委外发料齐套
4. PR 智能审核
5. 单价智能复核
6. 打样管理

### 8.2 现有页面增强

1. `production` 计划详情页增加预测、备料和齐套侧栏
2. `inventory` 物料详情页增加安全库存、缺口、价格波动分析
3. `approval` 审批页增加 PR 审核建议摘要
4. `message` 中承接采购、仓库、研发的提醒消息

## 9. 消息与审批联动

### 9.1 消息触发点

1. 预测生成完成
2. 备料评审待处理
3. 委外订单缺料
4. 仓库待备料
5. 发料完成待通知
6. PR 规则命中异常待人工确认
7. 单价异常待议价
8. 样品到货待领样
9. 领样超时二次提醒

### 9.2 审批触发点

1. 备料评审单
2. 异常 PR 人工复核
3. 高风险单价复核结论确认

## 10. 验收设计

每个业务场景都必须满足以下闭环标准：

1. 可创建正式业务单据
2. 可自动计算 / 自动识别
3. 可展示结构化结果
4. 可消息提醒
5. 可人工确认或处理
6. 可留痕审计
7. 可统计查询

### 10.1 需求预测

1. 能对产品生成预测计划
2. 能记录历史输入快照
3. 能形成建议备料量
4. 能回看历史预测准确率

### 10.2 委外发料

1. 能依据 BOM 与库存做齐套校验
2. 能标记缺料与规格不符
3. 能驱动仓库备料和采购跟进
4. 能闭环到发料完成

### 10.3 PR 审核

1. 能识别异常 PR
2. 能支持批量周期审批
3. 能支持随时一键审批
4. 能保留规则命中依据

### 10.4 单价复核

1. 能上传规格书
2. 能解析关键参数
3. 能给出成本拆解
4. 能对比历史价和核价标准
5. 能标记异常并保存结论

### 10.5 打样闭环

1. 能登记打样
2. 能自动生成编号
3. 能记录到货
4. 能提醒研发领样
5. 能跟踪超时和确认记录

## 11. 实施策略

第一阶段按以下顺序推进：

1. 建立 `apps.supply_chain` 模块骨架、模型、路由、权限
2. 完成需求预测与备料评审链路
3. 完成委外发料齐套链路
4. 完成 PR 智能审核链路
5. 完成单价复核链路
6. 完成打样闭环链路
7. 完成驾驶舱、统计、菜单与测试

## 12. 风险

1. 现有 `BOMItem` 与 `InventoryItem` 不是强关联，需补正式映射
2. 现有生产 / 库存页面多为模板页，新增业务页数量较多
3. OCR / 单价拆解需要先落结构化结果，再谈复杂模型优化
4. `approval` 与业务单据联动需要明确回写边界

## 13. 结论

本方案以新增供应链智能协同域模块为核心，复用现有生产、库存、审批、消息、AI 底座，将计划、采购、仓库、研发相关需求转化为项目内可执行、可审计、可测试、可迭代的正式业务能力。
