# 供应链业务详情工作台设计

## 目标

在现有生产化数据与状态约束基础上，提高供应链日常操作效率。列表页用于筛选、扫描和进入待办，复杂业务处理统一进入详情工作台，避免在表格单元格中堆叠大表单。

## 现状问题

1. 预测、PR、核价和打样操作表单直接放在列表行内，信息密度失衡，移动端需要横向滚动后才能处理。
2. 单据来源、当前依据、历史结果和状态日志分散，操作人员难以在提交前完整判断。
3. 操作完成后统一跳回列表，用户需要重新搜索刚处理的单据。
4. 核价历史价格、委外齐套明细、PR规则依据和打样到货记录没有形成单据级工作视图。

## 采用方案

新增需求预测、委外发料、PR审核、单价复核、打样管理五类详情工作台。每个详情页遵循相同信息架构：

- 顶部：编号、状态、来源、负责人、更新时间和返回列表。
- 主区：业务关键数据、明细/依据、历史结果和状态时间线。
- 侧区：只显示当前状态允许执行的下一步操作，并明确操作效果。
- 来源：生产计划、领料申请、采购订单可跳转到项目原模块详情。

列表页删除复杂表单，仅保留业务摘要、风险/状态和“查看处理”按钮。批量PR审批仍保留在列表，因为它本身是跨单据操作。

## 数据与操作

- 预测详情：实时来源快照、最新预测、历次结果、备料评审和智能问答入口。
- 委外详情：生产计划/BOM来源、齐套明细、缺口、状态日志及合法状态动作。
- PR详情：来源申请、结构化审核条件、命中规则、审核依据和审批动作。
- 核价详情：采购来源、规格书记录、成本拆解、历史采购价格、结论及议价点。
- 打样详情：申请信息、到货照片状态、提醒次数、领样记录及超期状态。

现有动作接口继续复用，但成功后返回对应详情页。列表不再重复维护另一套操作逻辑。

## 验收标准

1. 五类详情路由均可访问并展示真实对象数据。
2. 列表不再包含预测参数、规则条件、成本拆解、上传和到货领样的大表单。
3. 每个详情页只显示当前状态允许的操作，操作完成后仍停留在详情页。
4. 来源对象具备可用的跨模块跳转，缺失来源时显示明确说明。
5. 桌面和移动端无页面级溢出，复杂明细在局部区域滚动。
6. 供应链自动化测试、系统检查和真实浏览器回归通过。
